Read-only architecture audit · no code changed · 2026-09-23 · revision 2, re-verified against source · full detail in docs/llm/model_agnostic_architecture_audit.md

The platform already has a working, DB-backed provider/model registry with full admin CRUD. What's missing is the one layer that matters for "admin picks the LLM per module/feature": today that choice is a hardcoded string literal compiled into each feature's source code.

Bottom line — the hard infrastructure (credential vaulting, provider CRUD, model discovery, a central router) is already built. The gap is a feature → model mapping that is admin-editable, expressed in a capability vocabulary rather than vendor product names, and actually consulted by the 76 call sites that currently hardcode a tier.
What most changes the plan — models/model_router.py:1666-1700 shows route() step 1a already resolves an arbitrary admin-registered model_id passed as model_hint, checked before the hardcoded _HINT_MAP. So the call-site migration is a one-argument substitution needing no router change, and gateway consolidation is not a prerequisite for shipping the capability.
Revision 2 — all 12 original findings were re-checked against source. 8 confirmed exactly, 4 corrected (3.2's count and its central claim, 3.4's drift evidence, 3.9's copy count, 3.11's scope), and 9 new findings added. Three of the new ones — budget-enforcement bypass, AgentStudio provider misrouting, and a governance kill-switch gap in the proxy — are live defects today that worsen the moment admins start assigning models, and have moved into Phase 0.
